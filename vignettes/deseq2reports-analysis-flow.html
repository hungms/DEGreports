Analysis flow: genes, pathways, and modules

Purpose

This vignette walks through each analysis section in deseq2reports and shows how genes, pathways, modules, and TF activities are computed and linked. Companion vignettes:

  • vignette("deseq2reports") — how to run the package
  • vignette("deseq2reports-modules") — function arguments and defaults

Organism (human / mouse) is inferred from gene symbols via detect_organism(); row names should be HGNC / MGI symbols.

Flow diagrams below need a network connection once (Mermaid CDN) when viewing the knitted HTML.

End-to-end pipeline flow

1. Quality control — which genes are kept?

Input. Raw counts in a DESeqDataSet.
Output. Filtered dds (size factors estimated); QC tables / library plots; per-sample detected-gene and total-transcript counts (Sample QC).

flowchart LR
  R[All genes] --> MT{remove_mt?}
  MT -->|drop MT| VDJ{remove_vdj?}
  MT -->|keep| VDJ
  VDJ -->|drop BCR/TCR pattern| XY{remove_xy?}
  VDJ -->|keep| XY
  XY -->|drop X/Y via gene_chr| EXPR[Expression filter]
  XY -->|keep| EXPR
  EXPR -->|cpm: drop bottom percentile by mean CPM| KEEP[Retained genes]
  EXPR -->|count: keep genes above min_count| KEEP
  EXPR -->|NULL: no expr filter| KEEP
  KEEP --> SF[estimateSizeFactors]

Defaults used by the orchestrator: filter_method = "cpm", cpm_percentile = 0.05. Metadata is stored on metadata(dds)$deseq2reports_qc for the report (including sample_qc_table).

2. Counts export and sample structure

Counts export writes raw, VST, rlog, and CPM matrices (plus a batch-corrected matrix when batch is set: ComBat-seq corrected raw counts for platform = "rnaseq", a ComBat-corrected VST matrix for platform = "microarray"). These are for downstream use; the DE model still uses the QC-filtered raw counts.

Distance / PCA (run_distance_pca):

flowchart TD
  D[QC dds] --> V[VST]
  V --> B{batch set?}
  B -->|ComBat-seq / ComBat for viz only| P[PCA + scree + loadings]
  B -->|none| P
  P --> A[PC–covariate association heatmap top 15 PCs]
  V --> S[Sample Spearman similarity heatmap]

Batch correction here does not change the DE design matrix – DESeq2 keeps using raw counts with batch as a covariate. The corrected matrix is shared with the sample-level modules (WGCNA, GSVA, ULM, VIPER, CSPA), so the PCA and those modules always agree on what was corrected. Association heatmap tests PC scores vs batch / grouping var / time (LRT) when those columns are passed as assoc_vars.

3. Differential expression — how are DEGs defined?

Contrasts. From var (length 1–3), expand_contrast_specs() builds pairwise and one-vs-rest labels. With two or three factors, each factor’s main effect is always expanded — its comparisons taken across every level of the other factors (C_vs_noC), fitted on all samples with an additive design so the other factors are adjusted for. include_interactions = TRUE adds difference-of-differences contrasts on top (C_vs_noC_x_K_vs_noK_in_CB: does the K effect differ between C and noC inside CB), each a combination of coefficients from a single fit of the product design on all samples. A factor with three or more levels is compared one-vs-rest (CA_vs_CB+CC_x_K_vs_noK_in_C), the pooled side being a mean of coefficients with equal weight per level.

Per contrast (run_diffexp / run_diffexp_pipeline):

flowchart TD
  D[QC dds + design] --> FIT[DESeq fit]
  FIT --> RES[results: LFC, SE, stat, pvalue, padj]
  RES --> SHR{shrinkage}
  SHR -->|ashr / apeglm / normal| LFC[Shrunk log2FoldChange]
  SHR -->|none| LFC2[Unshrunken LFC]
  LFC --> RANK[rank_score from ranking metric]
  LFC2 --> RANK
  RANK --> SIG["sig = padj less than alpha AND abs LFC greater than lfc_threshold"]
  SIG --> DIR[direction up / down / ns from sign of LFC]
  SIG --> PLOTS[MA, volcano, DEG table]

Fixed by the pipeline. shrinkage "ashr", alpha = 0.05, lfc_threshold = 0.5. ranking is still an argument and defaults to "log2FoldChange" (so rank_score ≈ LFC). Call run_diffexp_pipeline() directly to change the fixed values.

Gene-level objects used later:

  • Significant DEGs (sig) → CSPA selection, PPI seeds, multihit DEG bit
  • Full ranked list (rank_score) → GSEA ranks
  • Wald stat → contrast-level decoupleR / VIPER

4. CSPA surface markers

Among each contrast’s DEGs, intersect with Cell Surface Protein Atlas symbols (human list; mouse via orthologs), rank by |rank_score| / |LFC|, keep the top 25 per contrast (10 per degPatterns cluster in LRT mode), and plot all-sample VST heatmaps (per contrast + combined union).

flowchart LR
  DEG[sig DEGs] --> INT[Intersect CSPA gene list]
  INT --> TOP[Top n_markers by abs rank_score]
  TOP --> HM[VST heatmap all samples]

5. GSEA — how are pathways scored?

Ranks. For each contrast, genes are ordered by rank_score (same metric as DE). Duplicate symbols are collapsed (max |score|).

Gene sets. MSigDB collections via msigdbr (human sets; mouse genes mapped with orthologs when needed). Default collections exclude HALLMARK unless you add it.

Enrichment. Primary engine is fgsea (run_gsea / run_gsea_pipeline). Optional parallel clusterProfiler::GSEA() when run_clusterprofiler = TRUE.

flowchart TD
  DE[Per-contrast DE table] --> RK[Named rank vector]
  RK --> FG[fgsea vs each MSigDB collection]
  FG --> TAB[pathway NES padj leadingEdge]
  TAB --> BP[Barplot top_n_plot up and down by NES]
  TAB --> BC[Barcode panel]
  TAB --> LE[leadingEdge gene members]

Pathway significance for downstream overlap uses padj < alpha (pipeline alpha, default 0.05), pooling collections within one contrast.

6. GSEA leading-edge overlap

flowchart TD
  P[Significant pathways padj less than alpha] --> LE[Parse leadingEdge sets]
  LE --> J[Pairwise Jaccard matrix]
  J --> BC[binary_cut chooses k]
  J --> HC[hclust on 1 minus Jaccard]
  BC --> K[k]
  K --> CT[cutree hc at k]
  HC --> CT
  CT --> HM[Square heatmap + dendrograms]
  CT --> WC[Side word clouds]

Splits, dendrograms, and word clouds share the same cutree partition (k from binary_cut). Artifacts live under clusterprofiler/<contrast>/gsea_overlap/.

7. WGCNA — modules from co-expression (not DE)

Independent of contrasts: uses all samples’ VST profiles.

flowchart TD
  V[VST expression] --> SFT[pickSoftThreshold powers through 20]
  SFT --> CAP[Select power at most power_cap 15]
  CAP --> NET[blockwiseModules signed network]
  NET --> MOD[Modules by size; grey to Unassigned]
  MOD --> ME[Module eigengenes]
  ME --> TR[Correlate MEs vs grouping var]
  MOD --> HUB[Hub genes by abs kME]
  MOD --> ORA[fora ORA per module and collection]

Unassigned / grey is excluded from ORA (not a coherent module).

8. TF activity — decoupleR (CollecTRI + ULM)

  NET --> C[Contrast ULM on Wald stat]
  S --> SH[Sample TF heatmap]
  C --> CB[Contrast TF barplots]

10. STRING PPI

Seeds = significant DEGs (or WGCNA module members) → map to STRING → induced subgraph → community / hub layout. Embedded on DE and WGCNA report pages.

11. Multi-hit genes — integrating layers

Per contrast, each gene scores +1 for each layer that hits it:

Layer Hit rule
DEG sig
GSEA In any significant pathway leading edge (0/1)
VIPER Significant TF after ortholog map (padj < alpha)
decoupleR Significant source (p_value < alpha)
CSPA Selected CSPA marker for that contrast 
flowchart TD
  G[Genes] --> S[score = deg + gsea + viper + decoupler-tf + decoupler-ccc + cspa]
  S --> DIR[Split by DEG LFC sign up vs down]
  DIR --> TOP[Top top_n per direction]
  TOP --> PLOT[Bidirectional multihit barplot]

Shown on the dedicated Multihit HTML page (multihit/multihit.html, after VIPER in the nav).

Key differences from Wald mode:

  • Nested LRT full/reduced models via expand_lrt_specs() (no signed LFC ranking → no GSEA; cluster ORA instead).
  • Significant genes clustered with degPatterns; PPI / CSPA / TF / multihit are per cluster.
  • Multihit page shows tables (top 10 genes × LRT DEG / WGCNA / decoupleR / VIPER), not directional barplots.
  • Default CSPA is top 10 genes per cluster.

Minimal mental model

  1. Filter genes (QC) → expression universe for everything else.
  2. Test genes (DESeq2 Wald or LRT) → sig, ranks / LRT stat.
  3. Test pathways — GSEA on Wald ranks, or ORA on LRT clusters.
  4. Relate pathways (Jaccard overlap, Wald) and relate genes across methods (multihit).
  5. Optional structure: co-expression modules (WGCNA), TF networks (decoupleR / VIPER), protein networks (STRING), surfaceome (CSPA).
